# 検証方針

オーナーはコードを読まない。「正しく動く証拠」を、テスト結果とスクリーンショットで報告に残す。

## 4つの層
| 層 | 誰が | 何を | 道具 |
|---|---|---|---|
| 1. ロジック | Claude | 日付境界、ゴースト計算、予実比較などの正しさ | Swift Testing（ユニットテスト） |
| 2. 画面 | Claude | 受け入れ基準どおりに画面が動くか。ライト/ダーク、文字サイズ最大でも崩れないか | XcodeBuildMCP（シミュレーター起動・UI操作・スクショ）、XCUITest（GitHub Actions で全件） |
| 3. 時間の再現 | Claude | 「1週間後」「深夜3:59」など時間に依存する挙動 | Clock注入とデモデータ（起動引数） |
| 4. 実機専用 | オーナー | ブロック、Screen Time許可、通知の実際の届き方 | Claudeが報告に手順を書き、オーナーがiPhoneで確認 |

## ブラウザ確認（Claude in Chrome）との対応
別アプリで行っているブラウザ確認に相当するのは層2。Claudeがシミュレーターを操作し、スクリーンショットを撮って自分で確認する。Claude in Chrome自体はネイティブアプリには使えない（段階4でWebダッシュボードを作れば使える）。

## 完了の定義
作業を「完了」と報告できるのは、次を全て満たしたとき。
- ビルドが通る
- CI（ユニットテスト全件・UI テスト全件）が通る
- 該当する受け入れ基準のうちClaude担当分を、シミュレーターで確認しスクショを添付した
- 実機専用の項目がある場合、オーナー向けの確認手順を報告に書いた
- 変更に合わせてdocsを更新した
- 報告を非公開の focus-app の docs/reports/ に書いた

## テストの回し方（[ADR-0021](../decisions/0021-github-actions.md)）
テストは GitHub Actions（GitHub の Mac）で回す。この Mac で回すのは急ぎのときだけ。

| いつ | 何を | どう回す |
|---|---|---|
| PR を出す・push する | ユニットテスト全件と UI テスト全件 | 自動（PR 用の CI）。ビルド1回 → 3台で同時に回す。約20〜30分 |
| main にアプリが変わるコミットが入る | ユニットテストと UI テストの全件 → TestFlight に送る | 自動（TestFlight 用の CI）。失敗したら送らない |
| 失敗したテストを手元で直す・報告用の撮影 | 必要なものだけ | この Mac の `scripts/test.sh`（下） |

- CI のシミュレーターは、この Mac と同じく iPhone 18 Pro・日本時間。テストは日本語・日本の設定で回す（xcodebuild の -testLanguage ja -testRegion JP）
- 塊1はユニットテスト全件と UI テストの1/3、塊2・3は UI テストの残り
- UI テストは1回だけやり直す。やり直して通ったものは、CI の警告に名前が出る（不安定なテストとして直す）
- docs・.claude・*.md だけの PR では Mac を使わない
- 失敗したときのログと結果（xcresult）は、CI の Artifacts「test-results-<塊>」に7日残る
- main は「CI OK」が通らないとマージできない。通ったら自動でマージされる（ADR-0010）

### この Mac で回すとき（[ADR-0020](../decisions/0020-test-queue.md)）
いくつものチャットが同時に開発しているので、この Mac では順番待ちにして回す。道具は `scripts/test.sh` ひとつ。始める前に CPU の負荷を確かめ、バックグラウンドで実行する。

| 何を | どう回す |
|---|---|
| ユニットテスト全件と、指定した UI テスト | `scripts/test.sh ui <対象...>` |
| 全件 | `scripts/test.sh all` |
| 報告用の撮影 | `scripts/test.sh tour <対象...>` |

- 同時に走るのは、ビルドとテストを合わせて Mac 全体で**2つまで**。3つ目からは待つ
- 2つ目は、メモリに余裕があるとき（macOS の判定が「通常」のとき）だけ使う。混んでいるときは自動で1つずつになる
- UI テストは6件ずつの塊に分けて並ぶ。1つのチャットが10分占有せず、各チャットの塊が順番に流れる
- 同じシミュレーターを2つのテストが同時に使うことはない
- `scripts/test.sh all` は、始める前に止まっていたシミュレーターを終わったら止める。普段の確認では、撮り終えたら止める（起動したままだと、何もしなくてもメモリと CPU を使う）
- 何かで止まったまま順番を塞がないよう、1つの塊が30分を超えたら打ち切る。テスト中にアプリが落ちたときの診断集め（最大10分）もしない
- 直接テストを動かす命令（`xcodebuild test`、XcodeBuildMCP の `test_sim`）は Claude Code のフックで止め、`scripts/test.sh` を使うよう案内する。例外は、実機で本物の時間を待つ確認（`REAL_WAIT=1`）だけ
- いま走っているもの・待っているものは `scripts/test.sh status` で見られる
