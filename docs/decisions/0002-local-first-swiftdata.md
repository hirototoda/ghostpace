# 0002. ローカルファースト、SwiftData＋Repository層
## 背景
個人用でオフラインでも確実に記録したい。一方で将来の同期・Notion連携の余地は残したい。
## 決定
データは端末内のSwiftDataに保存する。読み書きはRepository層に集約し、画面から直接触らない。全エンティティにUUIDと更新日時を持たせる。
## 理由
最初からサーバーを作ると段階1が遅れる。Repository層があれば、裏に同期処理を足すだけで段階4に移れる。
## 影響・トレードオフ
段階4までは端末故障でデータを失う可能性がある。必要なら段階3でファイル書き出しによるバックアップを前倒しする。
