# 0010. テストが通れば Claude が PR を自動でマージする
## 背景
当初は、オーナーが報告を読んでから自分でマージする案だった。オーナーの選択は「テストが通れば Claude が自動でマージし、オーナーは後から報告を読む」。
## 決定
次の条件をすべて満たしたら、Claude が GitHub 上で PR をマージする。
- ビルドとユニットテストがすべて成功している
- 振る舞いを変えた場合は、同じ PR で docs を更新している
- docs/reports/ に報告を書き、PR に載せている

例外（提案）：保存データの形を変える PR（マイグレーションを伴うもの）は、記録を失うおそれがあるため（NFR-02）、オーナーの確認を待つ。
## 理由
オーナーの作業待ちで開発が止まるのを防ぐ。
## 影響・トレードオフ
オーナーが確認するのはマージした後になる。問題が見つかったら、Claude が元に戻す PR か修正の PR を出す。
