# iOSの制約（主にScreen Time API）

設計に影響する制約。「要検証」は段階2の最初に実機で確かめ、結果をここに追記する。

## 確定している制約
- **アプリ別の使用時間の生データは取り出せない**。DeviceActivityReport拡張の中で表示はできるが、外部への書き出し・通信はできない。→ 分析は自前で記録するデータ（セッション、ShieldEvent、閾値イベント）を中心にする
- **ブロック対象のアプリ名は読めない**。FamilyActivityPickerで選んだ不透明なトークンとして扱う
- **Screen Time APIはシミュレーターで動かない**。実機検証が必須
- **シールドから直接アプリを開けない**。解除後はユーザーが開き直す
- **拡張機能は別プロセス**。本体とのデータ共有はApp Group経由。拡張はメモリ制限が厳しい
- **バックグラウンドでタイマー処理は続かない**。開始時刻を保存して差分で計算する

- **Screen Time の機能を TestFlight・App Store で配るには Apple の許可（Family Controls (Distribution)）が要る**。申請は開発者アカウント（チーム）に1回。**2026-10-01 に許可が出た**。そのあと開発者サイトの Identifiers で、本体と拡張機能の4つの ID それぞれの Additional Capabilities で「Family Controls (Distribution)」をオンにする必要があった（しないと書き出しで「プロファイルに Family Controls が入っていない」エラー）。Release にも同じ許可を入れ、`scripts/testflight.sh --no-upload` で書き出せることを確かめた
- **FamilyActivityPicker の印はアプリから付けておけない**。案内の文で選んでもらう
- **シールドに置けるのは文字・アイコン・ボタン2つまで**。長押しなどの操作は置けない。ボタンの結果は「閉じる」「そのまま」「シールドを出し直す」のどれかで、別のアプリ（GhostPace 含む）を直接開けない。→ 「開く」で通知を出し、そこから GhostPace の長押しの画面へ移る（[app-blocking.md](../product/features/app-blocking.md)）
- **自動でブロックに戻すスケジュール（DeviceActivitySchedule）は最短15分**。→ どの長さでも「戻す時刻＋15分」で終わるスケジュールにし、15分前の「終わる前の合図」（warningTime）で戻す。実機で「スケジュールの終わり」の合図は届かず（GhostPace を開くまで戻らなかった）、「終わる前の合図」は届いた（2026-10-01、5分で確認）ため。終わりの合図は予備として残す。時刻は分単位なので、期限を分に切り上げる（戻るのは最大1分遅れる）。拡張機能が動かなかったときに備え、GhostPace を開いたときにも時刻を見て戻す
- **「全部ブロック、ただしリストは除く」（`.all(except:)`）は、除いたアプリまで止まることがある**（Apple の掲示板に報告あり。ほかの Screen Time を使うアプリの許可が残っていると起きるという声がある）。→ 集中中の全部ブロック（BLK-04）は実機で確かめる。起きたら、ほかのアプリの Screen Time の許可を外してもらう。電話・メッセージなど一部のアプリはそもそも止められない
- **`.all()` でも止まらないアプリがある**：電話・メッセージ・設定のほか、Safari などいくつかの iPhone のアプリは止まらないという報告がある。**GhostPace 自身が止まるかは分からない**（止まると一時停止も長押しもできないので、「集中中も使うアプリ」に GhostPace を入れてもらう案内を出す）。どちらも実機で最初に確かめる
- **ゲーム・SNS の時間の切り替えも DeviceActivitySchedule**（最短15分）。始まりは「始まりの合図」（実機で届くかまだ確かめていない）、終わりは開けた時間と同じく「終わる前の合図」で戻す。合図が届かなかったときは、GhostPace を開いたときに決定表で合わせる。**同時に見張れるスケジュールは1アプリ20程度まで**。ゲーム・SNS の時間は1日3つまで（並べたものはつなげる）なので、使うのは最大3つ（`unblock-0〜2`）＋開けた時間の1つ
- **睡眠はヘルスケア（HealthKit）から読む**（DTX-02）。読む許可が要る（書かない）。HealthKit の entitlement・Info.plist の説明文（読む NSHealthShareUsageDescription と、書かなくても必要な NSHealthUpdateUsageDescription。後者がないと App Store へのアップロードで止められた、2026-10-02）・App Store のプライバシーの表記が要る。開発者サイトでアプリの ID に HealthKit を付ける（2026-10-02 オーナーが設定）。**読む許可を断ったかどうかはアプリから分からない**（記録がないのと同じに見える）。Garmin などの睡眠は、そのアプリが同期したときにヘルスケアに入るので、起きてすぐは入っていないことがある。Garmin の睡眠がヘルスケアにどう入るか（「寝ていた」か「ベッドにいた」か）は実機で確かめる

## 要検証
- 15分以上でも「終わる前の合図」で選んだ時刻どおりに戻るか（実機。2026-10-01 の変更後）
- 閾値イベントの粒度と上限数（使用時間の近似 ANA-02 の実現性）
- Family Controls の開発用の許可で、個人の実機常用に支障がないか（開発用の版の期限・再インストールで許可や対象の選択が消えないか）
- シールドが出し直される頻度（「シールドが出た」の記録が実際の回数とどれくらいずれるか）
- シールドに動的な値（ゴースト差）をどこまで表示できるか。App Group経由で最新値を渡す案
