# データモデル

## 要点（オーナー向け）
- 端末に保存するのは、下の6種類（カテゴリ、ブロック名、1日の計画、計画ブロック、タイマーの記録、計画のテンプレート）。段階1a で保存を始めた（2026-09-30）
- 記録は消さない方針：日中に消した計画ブロックは「消した印」をつけて残す。アーカイブしたカテゴリの記録も読める
- 保存データの形は「版番号つき」。形を変えるときは次の版を足し、前の版のデータを読めることをテストしてから出す（NFR-02）
- 第2版（2026-10-01）：1日の計画に目標時間、計画のテンプレートを足した。第1版のデータはそのまま読める（移行テストで確認）。振り返りはメモを取らないので保存しない
- アプリのブロックの記録は、拡張機能と共有する場所に別のファイルで置く（下の「ブロックの共有データ」）。保存データの版は変えない
- 習慣（PLN-08、2026-10-05）は端末の設定（UserDefaults）に置く。保存データの版は変えない
- ゲーム・SNS の時間（BLK-10、2026-10-02）は、計画ブロックのカテゴリに決まった ID（カテゴリの行は作らない）を入れて表す。保存データの形は変えない
- 第3版（2026-10-02。マージ前にオーナー確認）：睡眠の記録（SleepRecord、DTX-02）を増やした。新しい種類を足すだけで、第2版のデータはそのまま読める（移行テストで確認）
- 第5版（2026-10-06。マージ前にオーナー確認）：タイマーの記録に「申告」の印（isDeclared、TMR-13）を足した。空を許す項目（空は申告ではない）で、第4版のデータはそのまま読める（移行テストで確認）
- 第6版（2026-10-21。マージ前にオーナー確認）：一日の区切りの履歴（DayBoundaryChange、GHO-17）を増やした。日ごとにその日の区切りを覚え、変える前の日は朝4:00区切りのまま数える（[ADR-0023](../decisions/0023-day-boundary-evening.md)）。新しい種類を足すだけで、第5版のデータはそのまま読める（移行テストで確かめる）。振り返りの通知の時刻（端末の設定）は使わなくなる
- 第4版（2026-10-03。マージ前にオーナー確認）：カテゴリにデトックスのグループ（detoxGroupRaw）、睡眠に手で直す前の時刻（originalStartAt・originalEndAt）を足した。どちらも空を許す項目で、第3版のデータはそのまま読める（移行テストで確認）。掃除・料理・瞑想の組み替えと記録の付け替えは、データの形の移行とは別に、起動したときに1回だけ行う（[settings.md](../product/features/settings.md)「カテゴリの組み替え」）

## 共通
全エンティティ：`id: UUID`、`createdAt`、`updatedAt`（UTC）。時刻はUTC保存、`timeZoneId` を別に持つ。
エンティティ間は UUID で参照する（[ADR-0012](../decisions/0012-uuid-references-json-fields.md)）。同じ日の計画が重複して保存されていたら、更新日時が新しいものを使う。

## Category（カテゴリ）
| 項目 | 型 | 説明 |
|---|---|---|
| name | String | 勉強、仕事 など |
| countsAsFocus | Bool | 集中時間に数えるか（CAT-02） |
| sortOrder | Int | 並び順 |
| isArchived | Bool | 削除せずアーカイブ |
| detoxGroupRaw | String? | デトックスのグループ（DTX-03、第4版）：housework（家事）／exercise（運動）／rest（休み）。nil は上乗せなし（集中のカテゴリと、「なし」を選んだもの）。知らない値は nil として読む。集中かどうか（countsAsFocus）と違い、タイマーの記録には写さない（変えると過去の点も数え直す。2026-10-03 オーナー決定） |

初回起動時、カテゴリが（アーカイブを含めて）1つもなければ CAT-01 の6つ（とブロック名：家事に掃除・料理・洗濯、休みに瞑想・休憩）を保存する。デトックスから集中に切り替えると detoxGroupRaw は nil に戻す

最大7つ（8つ目は保存しない）。記録ではないので、消すときは行ごと消す（「消した印」の方針の例外）。
| 項目 | 型 | 説明 |
|---|---|---|
| name | String | 例：理想の休日（前後の空白は除く。空にはできない） |
| sortOrder | Int | 作った順 |
| blocksJSON | Data | ブロックの一覧（開始の時・分、長さ（分）、categoryId、projectId?）の JSON。読めなければ空のテンプレートとして扱う |

## DayBoundaryChange（一日の区切りの履歴・GHO-17、第6版）
設定で一日の区切りを変えるたびに1行足す。「この日から、この時刻で区切る」を持ち、日ごとの区切りはこれから決まる（[glossary.md](../product/glossary.md)「その日の区切り」）。過去の日の点を、その日の区切りで数え直すのに要るので、端末の設定（UserDefaults）ではなく記録と一緒に版番号つきで保存する（設定の画面の「一日の区切り」は、この表の一番新しい行を出す）。
| 項目 | 型 | 説明 |
|---|---|---|
| fromDayKey | String | この区切りを使い始める日の名前（例：2026-10-23）。この日から、次の行の fromDayKey の前の日まで使う |
| endMinutes | Int | その日の区切り（その日の終わり）を、日の名前の日の 0:00 からの分で持つ。22:00 → 1320、翌1:00 → 1500、翌4:00 → 1680。1200〜1680 の30分きざみ。範囲の外・30分きざみでない値は、近い30分きざみに丸めて範囲に収めて読む |
| timeZoneId | String | 変えたときの端末のタイムゾーン（参考。区切りの時刻は、その日を数えるときの端末のタイムゾーンの時刻として使う） |

- **日の範囲**：日の名前 D の終わり ＝ D の 0:00 ＋ endMinutes(D)。始まり ＝ 前の日（D−1）の終わり。endMinutes(D) は、fromDayKey が D 以前の行のうち一番新しいもの。なので一日の長さは区切りを変えた次の日だけ24時間でなく、16〜32時間になりうる（20:00 → 翌4:00 にした次の日は32時間）
- 一番古い行より前の日は、朝4:00区切り（endMinutes ＝ 1680。2026-10-21 の版より前の日。今までの dayKey と同じ）。行が0件のときは、すべての日をこの朝4:00区切りで数える（移す前の状態。下の「第5版から移すとき」で必ず1行足すので、ふつうは起きない）
- **日の名前**：その一日の中にある 12:00 の暦の日（区切りが 20:00〜翌4:00 のどれでも、一日の中に 12:00 はちょうど1回ある）。区切りが夜（20:00〜23:30）なら始まりの区切りの次の暦の日（10/20 22:00〜10/21 22:00 は「10/21」）、夜中（0:00〜翌4:00）なら始まりの区切りと同じ暦の日（10/21 1:00〜10/22 1:00 は「10/21」。今までの 4:00 区切りと同じ）（Claude 補足、Q46）
- **壁時計の時刻**：区切りは、端末の暦（注入された Calendar）の壁時計の時刻で決める。ほかの日と「同じ時刻でそろえる」（GHO-02）のも壁時計の時刻。夏時間の日（一日が1時間長い・短い）と、旅行でタイムゾーンが変わる日の揃え方は既知の制限（日本では夏時間は起きない。記録は保存済みの dayKey で引くので壊れない。[recording-spec.md](../plan/recording-spec.md)「非スコープ」の夏時間・旅行の行と同じ）
- **変えるとき**：fromDayKey ＝ 今の日の次の日の行を足す（次の日から効く、GHO-17）。同じ fromDayKey の行がすでにあれば（同じ日に何度も変えた）その行を書き換える。使い始めた行（fromDayKey が今の日以前）は書き換えない・消さない（過去の日の点を変えないため）
- 同じ fromDayKey が2つあれば、更新日時が新しいものを使う
- 次は Claude 補足（Q46（非公開の判断表））
  - **第5版から移すとき**（この版を最初に開いたとき）：fromDayKey ＝ そのときの日（朝4:00区切りで数えた日）の次の日、endMinutes ＝ 1320（22:00）の行を1つ足す。開いた日までは朝4:00区切りのまま（設定を変えたときと同じく次の日から）。例：10/22 15:00 に開く → 10/22 は 10/22 4:00〜10/23 4:00、10/23 は 10/23 4:00〜22:00（18時間）、10/24 は 10/23 22:00〜10/24 22:00
    - 移した日（4:00 区切りのまま）の振り返りの通知は、その日だけ 22:00 に出す。確定は今までどおり朝4:00なので、文面は今までの「今日を振り返りましょう」、振り返りの見出しは「今のところ・確定は朝4:00」。前に予約してあった振り返りの通知（設定の通知の時刻）は取り消し、区切りの決まりで予約し直す（[review.md](../product/features/review.md)「通知」）
    - 移した日をまたぐ一晩の睡眠は二重に数えない：移した日は今までどおりその夜の 0:00〜4:00 を自分の日に数え（翌朝決まったら数え直す、今までの決まり）、次の18時間の日にはその睡眠の 4:00 より後の分だけを付ける
  - 新しく入れた端末：その時点の日（22:00 区切りで数えた日）から 22:00 区切りにする。一番古い行の日は前の日（朝4:00区切り）の終わり＝朝4:00に始まってしまうので、その時点の日の前の日を fromDayKey にした 22:00 の行を足す（その時点の日が前の夜 22:00 から始まる。2026-10-21 実装時に書き方を直した）。「新しく入れた」は、タイマーの記録（FocusSession）も1日の計画（DailyPlan）も1つもないこと。どちらかが1つでもあれば、上の「第5版から移すとき」にする
  - 移したかどうかは、この表に行があるかで分かる（端末の設定に別の印は持たない）

## SleepRecord（睡眠の記録・DTX-02、第3版）
1日に1つ。その日の朝に終わった睡眠（睡眠の点は一晩分まとめてこの日に付ける。2026-10-21）。GhostPace を開いたときに、その日と前の6日のうちまだない日を設定の時刻で作る。今の日の分は朝4:00以降だけ作る（区切り〜3:59 はまだ寝ていないため。[digital-detox.md](../product/features/digital-detox.md)）。
| 項目 | 型 | 説明 |
|---|---|---|
| dayKey | String | 起きた日の名前（その日の区切りで分けた日。2026-10-21 の版より前は 4:00 区切りの日） |
| timeZoneId | String | |
| startAt / endAt | Date | 寝た・起きた時刻（UTC） |
| sourceRaw | String | health（ヘルスケア）／setting（設定の時刻）／manual（手で直した）。知らない値は manual として読む（置き換えない） |
| originalStartAt / originalEndAt | Date? | 手で直す前の時刻（第4版）。最初に手で直したときに、その直前の値（ヘルスケアか設定の時刻）を入れ、以後変えない。手で直していなければ nil。第4版より前に手で直した日は nil（比べられないので、直した時刻のまま数える） |

- その日のうち（その日の区切りまで。2026-10-21 までは翌朝4:00まで）だけ、health・setting をヘルスケアの値で置き換える。manual と、過ぎた日は置き換えない
- 同じ dayKey が2つあれば、更新日時が新しいものを使う

## FocusSession（タイマーの記録）
| 項目 | 型 | 説明 |
|---|---|---|
| dayKey | String | 開始時刻を含む日の名前（その日の区切りで分ける）。区切りをまたいでも開始した日のまま（タイムラインの日）。円の集中時間・ポイント・対戦は、区切りで区切った時間で数える（2026-10-03。2026-10-21 に 4:00 から区切りに） |
| timeZoneId | String | 開始したときの端末のタイムゾーン |
| planBlockId | UUID? | nilなら計画外 |
| categoryId / projectId | UUID / UUID? | 開始時のラベル |
| countsAsFocus | Bool | 開始したときにカテゴリが「集中に数える」だったか。後でカテゴリの設定を変えても、過去の記録の集中／デトックスは変わらない（2026-09-30 決定。確定した勝ち負けや金額を後から変えないため） |
| startAt / endAt | Date / Date? | endAtがnilなら実行中（同時に1つだけ） |
| plannedEndAt | Date? | 計画ブロックから開始したときのブロックの終了時刻。一時停止しても動かない |
| plannedDurationSec | Int? | 計画外で長さを決めたときの長さ。一時停止した分だけ終わりが後ろにずれる。計画ブロックから始めたときは、始めた時点のブロックの長さ（計画どおりの点の基準、GHO-16、2026-10-06 から。それより前の記録は空で、ブロックの今の長さで数える） |
| pausesJSON | Data | 一時停止の区間（開始・終了）の一覧の JSON。個数＝中断回数（TMR-03）。読めなければ空として扱う |
| originalEndAt | Date? | 終了時刻を早めたときの元の終了時刻（TMR-08）。nilなら未修正 |
| note | String? | |
| isDeclared | Bool? | 手動の記録（TMR-13、第5版。2026-10-20 までは「押し忘れの申告」）。true なら手で入れた記録（点は0.8倍）。nil・false はタイマーで計った記録。手動の記録は計画外（planBlockId が nil）でもよい（2026-10-21 から） |

- 数え方は保存しない：`plannedEndAt` か `plannedDurationSec` があればカウントダウン、どちらもなければストップウォッチ（TMR-07）
- 一時停止を除いて1分未満のセッションは保存しない
- セッションは一時停止の途中では終わらない（終わりが一時停止の中なら、その一時停止の開始を終了にする）
- 手動の記録（isDeclared が true）は、オーナーが消すと実際に削除する（手で入れた記録なので。タイマーの記録は消さない。2026-10-21、Q47（非公開の判断表））。保存データの形は変えない

## ブロックの共有データ（App Group、2026-10-01）
本体と拡張機能（別のプロセス）の両方が読み書きするので、SwiftData ではなく App Group（`group.com.hirototoda.focusapp`）に置く。SwiftData の版（SchemaV1/V2）とは別。アプリを消すと消える（記録と同じ）。

### BlockState（UserDefaults・App Group）
| 項目 | 型 | 説明 |
|---|---|---|
| selection | Data | iPhone 標準の選択画面で選んだ対象（FamilyActivitySelection を JSON にしたもの。中身は読めない印） |
| isEnabled | Bool | いつものブロックを始めたか |
| unlockedUntil | Date? | 開けている期限（UTC）。過ぎていればブロック中 |
| unlockRequestedAt | Date? | シールドの「開く」を押した時刻。2分以内に本体を開いたら長押しの画面を出す |
| isFocusBlocking | Bool | 集中のタイマーが動いていて一時停止していないか（BLK-04。ブロックを始めていなくても覚える）。拡張はタイマーを読めないので、これを決定表の入力にする。開けている間も覚えておき、戻すとき全部ブロックもかけ直す。シールドの見出しにも使う。前の版の状態にこの項目がなければ false として読む |
| unblockWindows | [{start, end}] | 今日の確定した計画のゲーム・SNS の時間（BLK-10、UTC。並べたものはつなげる）と、次の日の前の夜の分（区切り〜設定の睡眠の起きる時刻。次の日の下書き、なければ習慣。PLN-11）。区切りから朝の計画を確定するまでは、その日の下書きのもの。明日の計画を保存したときにも書く（区切りの時刻にアプリが動いていなくても、前の夜のゲーム・SNS の時間でブロックが外れるように。2026-10-21、Claude 補足、Q47）。本体が読み直すたびに計画から書き、変わったら iPhone のスケジュールを登録し直す。自動で切り替えるしくみ（拡張機能）はこれを正として決定表を計算する |
| isUnblocking | Bool | ゲーム・SNS の時間でいつものブロックを外しているか。変わったときだけ「外した／戻した」を記録する（本体と拡張の二重記録を防ぐ） |
| focusAllowSelection | Data? | 集中中も使うアプリ（BLK-02。FamilyActivitySelection の JSON）。nil なら全部ブロック |

### BlockEvent（JSON Lines・App Group の blockEvents.jsonl、足すだけで消さない）
| 項目 | 型 | 説明 |
|---|---|---|
| id | UUID | |
| occurredAt | Date | UTC |
| timeZoneId | String | |
| kind | enum | shieldShown / unlockRequested / holdCancelled / unlocked / reblocked / started / selectionLost / authorizationLost / authorizationRestored / unblockStarted / unblockEnded（started 以降は BLK-11、2026-10-01） |
| sinceAt | Date? | authorizationLost のとき、前に許可を確かめた時刻（そこから外れていたとみなす） |

- started は「ここからブロックが効いている」の印。前に selectionLost がなくても書くことがある（開こうとして選択が読めず、ブロックは残ったまま選び直したとき）
| unlockMinutes | Int? | 選んだ開ける長さ（kind が unlocked のとき。5〜60） |
| reblockReason | enum? | expired / manual / appForeground（kind が reblocked のとき） |
| activeSessionId | UUID? | 開けたときに動いていたタイマーの記録 |

- 分析（段階3、ANA-01）で SwiftData に取り込むかを決める。それまではこのファイルを正とする
- 知らない kind の行は読み飛ばす（壊れた行と同じ。消さない）
- 拡張機能は1行足すだけ（メモリの制限が厳しいため、読み込まない）

### WidgetSnapshot（UserDefaults・App Group、WID-01、2026-10-06）
ウィジェットに渡すその日の材料。アプリを開いたとき・記録や計画を変えたときに上書きする（記録ではないので版番号の対象外）。
| 項目 | 説明 |
|---|---|
| generatedAt / dayStart / dayEnd | 作った時刻と、その日の始まり・終わり（前の日の区切り・その日の区切り。2026-10-21 までは 4:00・翌4:00） |
| blocks | 今の計画のブロック（名前・開始・終わり・ゲーム・SNS か） |
| focusSeconds | 作った時刻までの今日の集中 |
| runningStart / runningEnd | 動いている集中のタイマーの、数え始め（一時停止中は nil）と予定の終わり（なければ nil） |
| ghostCurve | 先週の自分の集中の進み方（その日の始まりから10分ごとの、同じ時刻でそろえた先週の累計の秒。GHO-02）。先週の記録がなければ空 |

### ShieldRaceSnapshot（UserDefaults・App Group）
シールドに出す差の材料。本体が読み直すたび（起動・前面に来たとき・各操作の後・1分ごと）に書く。
| 項目 | 型 | 説明 |
|---|---|---|
| writtenAt | Date | |
| dayKey | String | その日の名前 |
| dayStart | Date | その日の始まり（前の日の区切り） |
| dayEnd | Date? | その日の区切り（2026-10-21 に足した）。シールドを出す時刻が dayStart より前か dayEnd 以降なら差を出さない（拡張は区切りの履歴を読めないので、dayKey を自分で数えず、これで決める）。前の版の材料にこの項目がなければ dayStart の24時間後として読む |
| focusSecAtWrite | Int | 書いた時点の今日の集中 |
| isFocusRunning | Bool | 書いた時点で集中のタイマーが動いていたか（一時停止中は false）。true なら書いた時刻からの分を足す |
| opponentPrefix | String | 「先週の自分より」「目標より」（ホームで選んだ相手。いなければいる方） |
| opponentCurve | [Int] | 相手の累積集中（その日の始まりから15分ごと、その日の長さぶん。24時間なら97点、25時間なら101点。秒）。相手がいなければ空。あいだは直線でつなぐ |

### 書き込みと時刻の決まり
- 記録のファイルには、1つの記録を1行として1回で書き足す（4つのプロセスが同時に書いても行が混ざらないように、追記モードで開いて1回で書く）
- 現在時刻は、本体は `AppClock`、拡張は `SystemClock` から取り、`BlockPolicy`・`ShieldRaceSnapshot` には引数で渡す
- 自動で戻すスケジュールは分単位なので、戻す時刻は期限を分に切り上げる（早く戻さない）。新しく開く・今すぐ戻すときは前のスケジュールを止めてから始める。戻すしくみは「今が期限以降で、まだ開けている」ときだけ戻す

## DailyReview（作らない・2026-10-01）
夜の振り返りは数字だけでメモを取らないので、保存しない。明日の計画は DailyPlan（draft）として保存する。

## 端末の設定（UserDefaults）
記録とは別に、通知のオンオフ（振り返りの通知の時刻は 2026-10-21 から使わない。一日の区切りは上の DayBoundaryChange）、計画の前の通知の分（初期5分前、TMR-12）、通知の説明を出したか、瞑想を足したか（2026-10-03 から使わない）、カテゴリを組み替えたか、「理想の休日」を入れたか、選んだ対戦相手、睡眠の時刻（初期 0:00〜7:00）、習慣（PLN-08。テンプレートのブロックと同じ形 [TemplateBlockValue] の JSON。項目がなければ「まだ決めていない」で、すでに使っている端末は起動時に前の日から引き継いでいた時刻で作る）、環境音の種類と音量（TMR-14）、その日に出したラップ・中間地点の帯（GHO-06。同じものを二度出さないため）、習慣の最初の案内を出す途中か（[daily-plan.md](../product/features/daily-plan.md)「習慣」）を置く（[settings.md](../product/features/settings.md)）。版番号の対象外（項目がなければ初期値で読む）。

## 算出値（保存しない）
- 集中時間：countsAsFocus（記録に残した値）が true のセッションの、一時停止を除いた時間の合計
- その日の始まり・終わり：DayBoundaryChange から決める（上の「日の範囲」）
- ゴースト累積曲線：7日前の日の名前のセッションを、同じ時刻でそろえて（7日ずらして）算出。先週の日の始まりより前は0、終わりより後は先週のその日の合計（GHO-02。区切りが同じ週は、今までの「日付境界からの経過時間で揃え、24時間を超える部分は切る」と同じ）
- デジタルデトックスの時間・ポイント（DTX-01・03）：ブロックの記録（始めた・許可・開けた・戻った）、計画のゲーム・SNS の時間、タイマーの記録、睡眠の区間から毎回計算する（[digital-detox.md](../product/features/digital-detox.md)）
- 参照先のカテゴリが見つからない記録は「不明」として表示し、記録は消さない（集中かどうかは記録に残した値のまま）
